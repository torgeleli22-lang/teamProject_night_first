# Lambda

서버는 **Lambda 함수 두 개**예요. 둘 다 콘솔 코드 탭에 그대로 붙여넣는 읽을 수 있는 코드이고, zip·빌드가 없어요.

```
화면 ──JSON──▶ jojo_api (함수 URL 하나)  ──▶ DynamoDB jojo_table · Bedrock Claude Haiku 4.5
                 │ 뒤에서 할 일(학습자 분석·개념 문제 생성)은 자기 자신을 다시 불러 실행
                 └──▶ jojo_generate_code (코드 문제 생성: 코드를 실제로 실행해서 확인)
```

| 폴더 | 함수 | 언어 | 하는 일 |
|---|---|---|---|
| [`api/`](api) | `jojo_api` | Python 3.13 | 화면의 모든 요청 + 학습자 분석·개념 문제 생성·기본 문제 넣기 |
| [`generate-code/`](generate-code) | `jojo_generate_code` | Node.js 22 | 코드 문제 AI 생성 + 실행 검증 (JavaScript 를 실제로 실행해야 해서 이것만 Node.js) |
| `tests/` | — | — | Python 단위 테스트 (`npm run test:lambda`) |

## 왜 이렇게 나눴나요? (최소 비용·최소 구성·최고 속도)

| | 이 구성 | 기능마다 함수를 따로 만들 때 |
|---|---|---|
| 콘솔에서 만들 함수 | **2개** | 9개 |
| 공통 코드(`common.py`) | **한 곳** | 함수마다 복사 |
| 화면 설정 변수 | **`API_URL` 하나** | 5개 |
| 콜드 스타트(오래 쉬다 첫 요청이 느림) | **드묾** — 모든 요청이 같은 함수를 데워 둠 | 기능마다 따로 식음 |
| 브라우저 연결 | **주소 하나라 HTTPS 연결을 한 번 맺고 계속 다시 씀** | 기능마다 새로 연결 (한 번에 0.1~0.3초) |
| 문제 데이터 메모리 보관 | 한 함수가 모아서 씀 → DynamoDB 읽기가 적음 | 함수마다 따로 읽음 |
| 요금 | Lambda 무료 사용량 안에서 0원에 가까움 | 같음 (요청 수는 같고, 콜드 스타트만큼 시간이 더 듦) |

코드 안의 속도 최적화
- 화면 하나에 필요한 학습 기록(풀이·하루 요약·개념 요약·분석)을 **DynamoDB 조회 한 번**으로 읽어요 (`common.learner_records`)
- 학습자의 '마지막 사용 시각'은 15분마다만 고쳐 써요 → 요청마다 하던 쓰기 1번이 줄어요
- 커리큘럼은 함수 안의 `content.json` 에서 읽어요 (DynamoDB 를 거치지 않음)
- 문제 데이터는 메모리에 두고 30초마다 바뀌었는지만 확인해요

**원본은 이 폴더예요.** 콘솔에서 고쳤다면 같은 내용을 이 폴더에도 반영해 주세요 (팀원과 공유, 변경 기록, 자동 검사 `npm run smoke`).
만드는 방법: [`docs/DEPLOY_LAMBDA.md`](../docs/DEPLOY_LAMBDA.md) · 내 컴퓨터에서 실행: `npm run api`
