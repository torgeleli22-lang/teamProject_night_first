# AI 문제 생성 기준 (초안 — 팀 논의용)

> 코드: `src/lib/content/policy.ts` (숫자는 `POLICY` 한 곳에서 바꿀 수 있음) · 테스트: `tests/policy.test.ts`
> 관리자 화면 `/admin` 에서 칸별 재고·수요·생성 기록을 확인할 수 있습니다.

## 기본 원칙

1. **생성 단위는 "칸" = 개념 × 난이도.** 한 번 생성하면 코드 1개 + 6가지 유형(객관식·주관식·빈칸·셔플·실행 결과 예측·오류 찾기) 문제 세트가 만들어진다.
2. **생성된 문제는 모든 학습자가 공유한다.** 그래서 생성 비용은 사용자 수가 아니라 칸 수에 비례한다.
3. **"난이도·유형을 바꿨다"는 이유만으로는 생성하지 않는다.** 판단 기준은 **재고(그 칸의 공개 문제 수)** 와 **수요(그 칸을 다 풀어버린 학습자 수)** 다.
4. **검증을 통과한 것만 공개한다.** 실제 실행 검증 + 저비용 모델 검수 → 실패하면 한 번 재생성 → 그래도 실패하면 반려(비공개, 보고서 보관).
5. **사용자가 기다리는 경로에 생성을 넣지 않는다.** 생성은 백그라운드. 그동안 학습자는 가까운 난이도의 기존 문제로 계속 학습한다.

## 생성 트리거 4가지

| # | 트리거 | 언제 | 현재 값 |
| --- | --- | --- | --- |
| ① | 출시 전 채우기 | 관리자가 실행. 생성 대상 칸마다 최소 재고까지 | 칸당 **12문제** (≈ 세트 2개) |
| ② | 재고 하한 | 학습자가 고른 칸의 공개 문제가 최소 재고 미만 | 12문제 미만 |
| ③ | 여러 학습자 소진 | 그 칸에서 안 푼 문제가 4개 미만인 학습자가 최근 7일 동안 **2명 이상** | 4개 / 2명 / 7일 |
| ④ | 맞춤 복습 | 10문제마다 하는 학습자 분석에서 혼동(예: map과 filter)이 발견되고, 그 칸에 복습할 문제가 부족할 때 그 혼동을 겨냥한 세트 생성 | 학습자당 하루 1회, 안 푼 문제 8개 미만 |

생성하지 않는 경우:
- 한 학습자만 칸을 소진 → 수요만 기록하고 **틀린 문제·오래전에 푼 문제를 다시 출제**
- 칸이 **최대 40문제**(≈ 세트 7개)에 도달 → 더 만들지 않고 재출제
- **생성 대상이 아닌 칸**: 단원 성격에 맞지 않는 난이도(예: 변수 심화), DOM·이벤트·fetch(서버에서 실행 검증이 안 됨 → 사람이 작성)

## 비용 안전장치

- 같은 칸을 동시에 두 번 생성하지 않음
- 하루 생성 상한 **30회** (`AI_GENERATION_DAILY_LIMIT`)
- 월 예산 **$30** (`AI_MONTHLY_BUDGET_USD`, AI 사용량 기록으로 추정해 넘으면 생성 중단)
- 참고: 코드 세트 1개 생성 비용은 대략 $0.2~0.4 로 가정 (Opus 출력 1만여 토큰 + 재생성 가능성). 실제 측정 후 조정 필요

## 개념별 생성 허용 난이도 (초안)

| 단원 | 개념 | 허용 난이도 |
| --- | --- | --- |
| JavaScript 기초 | 변수, let/const, 데이터 타입, 연산자 | 1~3 |
| 프로그램 흐름 | if/else, switch, for, while | 1~3 |
| 데이터 | 배열, 객체, 문자열 | 2~4 |
| 함수 | 함수 선언, 매개변수/반환값, 화살표 함수, 스코프 | 2~4 |
| 배열 활용 | map, filter, forEach, find, reduce | 3~5 |
| 브라우저 | DOM, 이벤트 | 사람 작성만 |
| 비동기 | Promise, async/await | 4~5 (fetch 는 사람 작성만) |

현재 시드 기준으로 출시 전 채우기를 하면 약 60칸 · 코드 세트 100여 개가 필요하다 (`/admin` 에서 실시간 계산).

## 팀이 정해야 할 것

1. **최소 재고(12) / 최대 재고(40)** — 출시 비용과 문제 다양성의 균형. 최소를 낮추면 출시 비용이 줄지만 같은 문제를 다시 볼 확률이 커진다.
2. **수요 기준(2명 / 7일)** — 사용자가 적은 초기에는 1명으로 낮출지.
3. **허용 난이도 표** — 위 표가 수업 목표와 맞는지. 칸 수가 곧 출시 비용이다.
4. **맞춤 복습(④)을 MVP 에 넣을지** — 개인화의 핵심 차별점이지만 비용이 사용자 수에 일부 비례한다.
5. **월 예산 · 하루 상한** — AWS 계정/결제 검토 결과에 맞춰.
6. **반려된 콘텐츠 처리** — 버릴지, 관리자가 고쳐서 다시 검증할지 (현재는 보관만).
7. **품질 교체 트리거(다음 단계 후보)** — 정답률이 비정상적으로 높거나(98%↑) 낮은(15%↓) 문제를 검토·재생성 대상으로 올릴지.
