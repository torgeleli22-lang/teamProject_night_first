# AI 사용 기준 (코드 리딩 노트)

> AI 는 일곱 가지 작업에만 씁니다. 모두 `lambda/api/common.py` 의 `ask_ai()` 로 부르고, 응답은 정해진 JSON 모양(도구 입력)으로 받아 검사합니다.
> AI 를 쓸 수 없을 때(관리자가 끔 · `AI_MODE=off` · 월 예산 · 요청 한도 · 형식 오류)는 **AI 없이 같은 화면이 계속 동작**합니다.
> 관리자 화면 `/admin/` 에서 작업별 호출 수·토큰·이번 달 추정 비용을 봅니다.

| 작업 (`OPS#USAGE` 이름) | 파일 | 언제 | AI 없을 때 |
| --- | --- | --- | --- |
| 주제 판정 `topic_check` | `topics.py` | '직접 적기' 주제를 낼 때 | `rule_check`: 금지어 → 부적절, 막연한 말 → 제안 3개, 큰 단어(입문·초급은 엄격) → 좁힌 주제 |
| 연습 코드 만들기 `code_generation` | `practice.py` | 코드 받기, 더 쉽게·더 어렵게 | `samples.py`·`samples_js.py` 의 예시 코드 (같은 언어·난이도, 같은 주제 → 최근에 안 푼 주제) |
| 연습 코드 검토 `code_check` | `practice.py` | 연습 코드를 만든 뒤 (규칙 검사를 통과한 코드만) | 검토 없이 규칙 검사(②)만 믿고 통과 |
| 내 코드 분석 `code_inspection` | `inspect_code.py` | '메모하러 가기' | `rule_analysis`: 문법 요소로 난이도, 함수마다 조건·반복 덩어리를 ※ 로 |
| 빨간펜 첨삭 `review` | `review.py` | '첨삭 받기' | `rule_review`: 겹치는 ※ 지점의 핵심 표현이 메모에 얼마나 있는지로 ○△✕ |
| 다시 써 보기 채점 `review_retry` | `review.py` | 첨삭 뒤 '다시 채점 받기' | `rule_retry`: 첫 첨삭과 같은 핵심 표현 규칙 |
| AI 튜터 대화 `tutor_chat` | `tutor_chat.py` | 첨삭 결과에서 메모마다 '묻기' | `rule_answer`: 첨삭 코멘트 → 예시 값으로 따라가기 → 모범 설명 순서로 조금씩 더 |

## 1. 주제 판정
- **ok**: 그 난이도의 길이(입문 10~20줄, 초급 25~45줄, 중급 100~130줄(JavaScript 100~125줄), 고급 180~270줄) 안에서 기능 하나를 보여 줄 수 있는 구체적인 생활 속 주제 → 바로 코드 만들기
- **vague**: 무엇을 하는 코드인지 알 수 없음 ("재미있는 거") → 구체적인 주제 3개
- **too_big**: 기능이 여러 개 ("쇼핑몰 만들기") → 첫 제안은 기능 하나로 좁힌 주제. 난이도가 낮을수록 엄격하게
- **inappropriate**: 해킹·불법·폭력·혐오·성적인 내용이거나 코드와 관계없음 → 만들지 않음, 화면은 "랜덤으로 뽑을게요"
- 주제는 50자까지. 학습자가 적은 글은 `<topic>` 안의 데이터로만 다룬다

## 2. 연습 코드 만들기
- AI 가 `title`, `code`, `marks`(※ 입문 1곳, 초급 2곳, 중급 3곳, 고급 5곳)를 만든다. ※ 마다 `startLine`·`endLine`(그 줄의 글자 그대로), `startNo`·`endNo`(줄 번호 힌트), `why`, `explanation`(모범 설명), `keywords`, `concept`(개념 꼬리표 8가지 중 하나 — 틀리거나 없으면 서버가 규칙으로 추정, 답 전체를 버리지 않음)
- **집중 연습** (`focus`): '내 공부'에서 약한 개념을 고르면 그 흐름이 코드 곳곳에 나오고 ※ 의 절반 이상이 그 개념이 되게 지시. AI 를 못 쓰면 그 개념이 든 예시 코드
- **단계별 교정** (모든 난이도, 코드는 한 번도 실행하지 않음): ① 출제 → ② 규칙 검사 → ③ AI 검토 → 통과한 코드만 화면에
- ② 규칙 검사 (`check_generated`, 비용 없음)
  - Python: `ast.parse` 로 문법, `py_ast_problems` 로 쓰지 않기로 한 모듈(os·sys·subprocess·socket·urllib 같은 파일·네트워크·운영체제 모듈과 표준 라이브러리가 아닌 모듈. random·time·datetime 은 됨)·함수(input·open·eval 등), **어디에도 정의하지 않은 이름**(오타, `totl += 1` 포함), print 가 있는지
  - JavaScript: `js_shape_problems` 로 괄호·따옴표·템플릿 문자열·주석·정규식 짝, import·fetch·document·setInterval 등 (Math.random·Date 는 됨), console.log 가 있는지 (문자열·주석 안은 보지 않음)
  - 공통: 난이도별 줄 수 (최대 30·60·150·300, 중급은 최소 100·고급은 최소 120), ※ 줄을 코드에서 찾기 (글자 우선, 같은 줄이 여럿이면 번호 힌트에 가까운 줄), 겹치지 않는 ※ 입문 1곳·그 밖에는 2곳 이상
- ③ AI 검토 (`ai_check_code`, 작업 `code_check`, 답 최대 3000 토큰): 출제와 다른 역할의 AI 가 코드를 머릿속으로 한 줄씩 실행해 본다
  - `codeProblems`: 실행 오류(정의 안 한 속성, 타입, 빈 목록, 0 으로 나누기, 무한 반복)·난이도 불일치 → 코드를 다시 만들 문제
  - `marks[].ok=false`: ※ 모범 설명의 값·순서·결과가 코드와 다름 → **고친 설명·핵심 표현으로 바로 바꿈** (`fix_explanations`, 첨삭 기준이 틀리지 않게)
  - 실행할 때마다 달라지는 값(random·Math.random·지금 시각): 출제 규칙에서 `random.seed(숫자)`·정해진 날짜를 쓰게 하고 ※ 모범 설명은 그 값에 상관없이 맞는 흐름으로 쓰게 한다. AI 검토는 특정 값을 단정한 설명을 틀린 것으로 보고 고친다
  - 코드를 다시 쓰지 않고 문제 목록과 고친 설명만 돌려줘서 답이 짧다. AI 를 못 쓰면 ② 만 믿고 통과
- ②·③ 에서 걸리면 문제 목록과 방금 코드(줄 번호)를 주고 **한 번 더** 출제 (너무 길면 '기능 하나를 빼서 몇 줄 줄여 안내한 길이 안쪽으로'처럼 줄일 양까지 알려 줌, `TARGET_LINES`), 그래도 걸리면 예시 코드 (화면에 안내 문구). 걸린 이유는 관리자 'AI 호출 기록'에 '검사 걸림'으로 (AI 검토 문제는 `AI 검토:` 로 시작)
- 비용·시간: 코드 하나에 AI 2회(출제 + 검토)가 기본, 걸리면 최대 4회. 검토로 +40~60% 비용, +5~15초 (고급 +20~40초). 화면은 기다리는 동안 ①②③ 단계를 보여 준다 (`MakingCode`)
- **고급**: 실제 문제를 푸는 작은 프로그램 — 클래스·함수 6개 이상, 자료구조 2개 이상, 알고리즘 1~2개(최단 경로·동적 계획법·정렬·이진 탐색·재귀·백트래킹·그리디), 입력 검증·예외, 알고리즘 비교·요약. 줄 수를 채우려고 반복·주석·빈 줄로 늘리지 않게 지시. ※ 는 알고리즘의 핵심(값이 바뀌는 반복, 비교·선택, 되돌아가며 결과 만들기)에. AI 답 최대 16000 토큰(중급 10000, 입문·초급 3000), 1~2분 걸림. 랜덤 주제는 `ADVANCED_TOPIC_POOL`, AI 를 못 쓰면 예시 코드 2개(지하철 최단 경로 · 배달 주문 고르기)
- **더 쉽게·더 어렵게**: 지금 코드와 어려웠던 이유(너무 긺·모르는 개념·흐름이 복잡)를 주고 주제는 그대로 다시 만든다. 처음 코드부터 **5번까지** (`rootCodeId`·`regenCount`), 난이도는 한 단계씩(입문~고급 안에서)

## 3. 내 코드 분석
- 화면에서 먼저: `.py` 확인, 300줄 확인, 민감 정보 가리기(`src/lib/secrets.ts`) → 가린 코드만 보낸다
- `POST /inspect` (AI 없음): 한 번 더 가리기, 함수·메서드 목록(들여쓰기로 끝 줄), 훑어본 난이도(규칙)
- `POST /inspect/start` (AI): 고른 함수 범위 안에서 난이도(1~3)·이유·※ 2~4곳. 범위 밖 ※ 는 버리고, 하나도 없으면 규칙 분석
- 올린 코드는 1일 뒤 DynamoDB TTL 로 지워진다. 코드는 `<user_code>` 안의 데이터로만 다룬다

## 4. 빨간펜 첨삭
- **누락(⬚)은 AI 없이** 정한다: ※ 범위와 겹치는 메모가 하나도 없으면 누락
- AI 는 메모마다 correct / partial / wrong, `comment`(1~2문장), `lookAt`(다시 볼 줄 1~3개), `model`(모범 설명)과 총평 `summary`, 누락 ※ 마다 힌트 한 문장을 낸다
- **코멘트 규칙 (가장 중요)**: 정답을 바로 알려 주지 않고, 다시 볼 곳(줄 번호·조건·값)을 짚어 스스로 고치게 한다. 정확하면 잘 짚은 점을 칭찬하고 하나 더 볼 점
- ※ 지점과 겹치는 메모의 모범 설명은 AI 가 아니라 코드를 만들 때 정해 둔 `explanation` 을 쓴다 (첨삭마다 기준이 흔들리지 않게)
- 메모는 20장·500자까지. 메모 글은 `<memo>` 안의 데이터로만 다룬다
- 모범 설명은 첨삭 결과에서 '모범 설명 보기'를 눌러야 보인다

## 5. 힌트 보고 다시 써 보기
- 첨삭 결과에서 정확(○)이 아닌 항목마다, 힌트(첨삭 코멘트)를 보고 같은 범위를 다시 설명해 본다. 처음 메모가 있으면 그 글에서 고쳐 쓴다
- 그 항목 하나만 다시 채점한다 (correct / partial / wrong + 코멘트 + 다시 볼 줄). 항목 하나에 **3번**
- 프롬프트에 처음 메모·처음 판정·힌트·모범 설명(채점 기준, 그대로 말하지 않기)·이전에 다시 쓴 것을 넣는다
- 코멘트는 무엇이 나아졌는지 먼저 짚고, correct 가 아니면 아직 빠진 것 하나를 줄 번호와 함께 짚는다 (정답을 바로 말하지 않음)
- 기록은 `CODE#<id>` / `REVIEW#<첨삭 시각>#RETRY#…` 에 저장. 처음 첨삭의 ○△✕ 개수는 바꾸지 않는다

## 6. AI 튜터 대화
- 첨삭을 받은 뒤, 메모별 첨삭 하나(가장 최근 첨삭의 항목)에 대해 묻는다. 메모 하나에 **10번**, 질문은 300자까지
- 시스템 프롬프트에 코드 전체(줄 번호)·그 범위·학습자 메모·판정·코멘트·모범 설명을 넣고, 지난 대화를 이어서 보낸다
- **튜터 규칙**: 이 코드와 범위를 이해하는 데만 답하고 새 코드를 대신 짜 주지 않는다. 처음에는 볼 줄과 생각할 질문으로 이끌고, 학습자가 이미 시도했거나 직접 설명을 원하면 예시 값을 넣어 줄 단위로 풀어 준다. 2~5문장
- 답과 함께 `lookAt`(다시 볼 줄 0~3개)을 받아, 화면에서 누르면 왼쪽 전체 코드에 표시한다
- 대화는 `CODE#<id>` / `REVIEW#<첨삭 시각>#CHAT#…` 에 저장되어 다시 열어도 남고, 읽을 코드와 함께 지워진다
