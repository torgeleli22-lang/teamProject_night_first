# AI 사용 기준 (코드 리딩 노트)

> AI 는 여덟 가지 작업에만 씁니다. 모두 `lambda/api/ai.py` 의 `ask_ai()` 로 부르고, 응답은 정해진 JSON 모양(도구 입력)으로 받아 검사합니다.
> AI 를 쓸 수 없을 때(관리자가 끔 · `AI_MODE=off` · 월 예산 · 요청 한도 · 형식 오류)는 **AI 없이 같은 화면이 계속 동작**합니다.
> 관리자 화면 `/admin/` 에서 작업별 호출 수·토큰·이번 달 추정 비용을 봅니다.

| 작업 (`OPS#USAGE` 이름) | 파일 | 언제 | AI 없을 때 |
| --- | --- | --- | --- |
| 주제 판정 `topic_check` | `topics.py` | '직접 적기' 주제를 낼 때 | `rule_check`: 금지어 → 부적절, 막연한 말 → 제안 3개, 큰 단어(입문·초급은 엄격) → 좁힌 주제 |
| 연습 코드 만들기 `code_generation` | `practice.py` | 코드 받기, 더 쉽게·더 어렵게 | `samples.py`·`samples_js.py` 의 예시 코드 (같은 언어·난이도, 같은 주제 → 최근에 안 푼 주제) |

## 1. 주제 판정
- **ok**: 그 난이도의 길이(입문 10~20줄, 초급 25~45줄, 중급 70~90줄, 고급 110~160줄) 안에서 기능 하나를 보여 줄 수 있는 구체적인 생활 속 주제 → 바로 코드 만들기
- **vague**: 무엇을 하는 코드인지 알 수 없음 ("재미있는 거") → 구체적인 주제 3개
- **too_big**: 기능이 여러 개 ("쇼핑몰 만들기") → 첫 제안은 기능 하나로 좁힌 주제. 난이도가 낮을수록 엄격하게
- **inappropriate**: 해킹·불법·폭력·혐오·성적인 내용이거나 코드와 관계없음 → 만들지 않음, 화면은 "랜덤으로 뽑을게요"
- 주제는 50자까지. 학습자가 적은 글은 `<topic>` 안의 데이터로만 다룬다

## 2. 연습 코드 만들기
기준 전체는 **`docs/GENERATION_STANDARD.md`** (학습 목표 → 코드 요건 → ※ 지점 → 모범 설명 → 합격 기준 → 실패 처리). 여기는 요약이에요.

- **세 번의 AI 호출, 코드는 서버에서 한 번도 실행하지 않음**
  1. ① 출제 `code_generation`: `title`, `code`, `marks`(※ 위치 `startLine`·`endLine`·번호 힌트, `why`, `concept`). **모범 설명은 여기서 쓰지 않는다**
  2. 규칙 검사 A `check_generated` (비용 없음)
     - Python: `ast` 로 문법, 금지 모듈·함수(파일·네트워크·운영체제, 표준 라이브러리가 아닌 것), **실행마다 결과가 달라지는 것**(random·time·secrets·uuid·now()·today()), 정의하지 않은 이름(오타), print
     - JavaScript: 괄호·따옴표·템플릿·주석·정규식 짝, import·fetch·document·setInterval, **Math.random·Date.now()·인자 없는 new Date()**, console.log
     - 난이도별 꼭 있어야 하는 것·쓰지 않는 것 (`py_structure`(ast)·`js_structure`(tree-sitter) 로 함수·클래스·예외·재귀·반복·조건 수를 셈, 실행하지 않음), 손으로 따라갈 크기(숫자로 정한 반복·목록 항목 수)
     - 줄 수 (한도 30·60·100·180, 중급 최소 60·고급 최소 100), ※ 정확히 1·2·3·5곳, 한 곳 6·8·12·15줄 이하, 겹침 없음, 중심 개념 1곳 이상
  3. ② 실행 추적표 `code_trace` (`trace_and_explain`): 완성된 코드를 새로 읽고 `flow`(실행 순서·분기·반복·변수 값, 최대 40단계)·`output`·※ 마다 `enter`·`steps`·`exit`·`branch`·`count` 를 먼저 쓰고, **그 사실만으로** 모범 설명·핵심 표현을 쓴다
  4. 규칙 검사 B `explanation_issues`: 꼭 지킬 것 = 빈 설명·300자 초과·가정 표현("예를 들어"·"예컨대"·"가령")·설명 안에 있는 핵심 표현 2개 미만 / 확인할 것 = 설명 속 숫자가 추적표·출력·코드에 없음 (줄 번호 제외). 설명에 없는 핵심 표현은 서버가 뺀다
  5. ③ 교차 검토 `code_check` (`ai_check_code`): **생성 쪽 추적표를 보여 주지 않고** 원본 코드에서 따로 추적(`trace`)한 뒤 판정. `codeProblems`(실행 오류·끝나지 않는 반복·난이도 불일치·실행되지 않는 ※·쓸모없는 코드) → 부분 수정(아직 안 썼으면) 뒤 ②·③ 다시, 아니면 다시 만들기 / `marks[].ok=false` → 고친 설명으로 교체. 규칙 검사 B 의 결과도 함께 알려 확인시킨다
  6. 검토가 고친 설명까지 규칙 검사 B 를 한 번 더 → 꼭 지킬 것이 남으면 다시 만들기
  7. 두 추적표를 서버가 비교해 기록 (`compare_traces`: ※ 지점별 나갈 때 값·반복 횟수, 출력) → `checks.traceAgree`·`outputAgree`
- 코드 요건·검토의 코드 문제는 먼저 **부분 수정** `code_fix` (`fix_code`·`apply_edits`): 줄 번호를 붙인 코드와 문제를 주고 바꿀 줄 범위만 받아 고친다 (문항당 1번, 줄 수 문제는 빼고). ※ 위치만 걸리면 ※ 다시 고르기 `mark_reselect`
- **학습자 등급** `grade` (기초·보통·전문가, `GRADES`): 난이도와 별개로 ※ 고르기와 모범 설명의 말투·깊이만 바꾼다. 교차 검토에는 주지 않는다
- 그래도 걸리면 문제 목록과 방금 코드(줄 번호)를 주고 **최대 2번 다시** 출제 (너무 길면 줄일 양까지, `TARGET_LINES`). 그래도 걸리면 예시 코드 (화면에 안내 문구). 걸린 이유는 관리자 'AI 호출 기록'에 '검사 걸림'으로
- 저장: 코드·※ 지점(모범 설명·핵심 표현)·`trace`·`checks`·`verification`(`ai_reviewed`·`rule_checked`·`sample_verified`). 화면에는 코드와 ※ 위치만 (`public_code`)
- **집중 연습** (`focus`): '내 공부'에서 약한 개념을 고르면 그 흐름이 코드 곳곳에 나오고 ※ 의 절반 이상이 그 개념이 되게 지시. 그 개념이 그 난이도에서 쓰지 않는 요소면 나오는 난이도로 올리고 안내 (`focus_level`). AI 를 못 쓰면 그 개념이 든 예시 코드
- 비용·시간: 보통 AI 3회(출제·추적·검토), 최대 9회. 문항당 입문·초급 20~40초, 중급·고급 1~3분. 화면은 기다리는 동안 ①~④ 단계를 보여 준다 (`MakingCode`)
- **더 쉽게·더 어렵게**: 지금 코드와 어려웠던 이유(너무 긺·모르는 개념·흐름이 복잡)를 주고 주제는 그대로 다시 만든다. 처음 코드부터 **5번까지** (`rootCodeId`·`regenCount`), 난이도는 한 단계씩(입문~고급 안에서)

## 3. 내 코드 분석
- 화면에서 먼저: `.py` 확인, 300줄 확인, 민감 정보 가리기(`src/lib/secrets.ts`) → 가린 코드만 보낸다
- `POST /inspect` (AI 없음): 한 번 더 가리기, 함수·메서드 목록(들여쓰기로 끝 줄), 훑어본 난이도(규칙)
- `POST /inspect/start` (AI): 고른 함수 범위 안에서 난이도(1~3)·이유·※ 2~4곳. 범위 밖 ※ 는 버리고, 하나도 없으면 규칙 분석
- 올린 코드는 1일 뒤 DynamoDB TTL 로 지워진다. 코드는 `<user_code>` 안의 데이터로만 다룬다

## 4. 빨간펜 첨삭
- **누락(⬚)은 AI 없이** 정한다: ※ 범위와 겹치는 메모가 하나도 없으면 누락
- AI 는 메모마다 correct / partial / wrong, `comment`(1~2문장), `lookAt`(다시 볼 줄 1~3개), `model`(모범 설명)과 총평 `summary`, 누락 ※ 마다 힌트 한 문장을 낸다
- **코멘트 규칙 (가장 중요)**: 정답을 바로 알려 주지 않고, 다시 볼 곳(줄 번호·조건·값)을 짚어 스스로 고치게 한다. 정확하면 잘 짚은 점을 칭찬하고 하나 더 볼 점
- ※ 지점과 겹치는 메모의 모범 설명은 AI 가 아니라 코드를 만들 때 정해 둔 `explanation` 을 쓴다 (첨삭마다 기준이 흔들리지 않게)
- 메모는 20장·500자까지. 메모 글은 `<memo>` 안의 데이터로만 다룬다
- 모범 설명은 첨삭 결과에서 '모범 설명 보기'를 눌러야 보인다

## 5. 힌트 보고 다시 써 보기
- 첨삭 결과에서 정확(○)이 아닌 항목마다, 힌트(첨삭 코멘트)를 보고 같은 범위를 다시 설명해 본다. 처음 메모가 있으면 그 글에서 고쳐 쓴다
- 그 항목 하나만 다시 채점한다 (correct / partial / wrong + 코멘트 + 다시 볼 줄). 항목 하나에 **3번**
- 프롬프트에 처음 메모·처음 판정·힌트·모범 설명(채점 기준, 그대로 말하지 않기)·이전에 다시 쓴 것을 넣는다
- 코멘트는 무엇이 나아졌는지 먼저 짚고, correct 가 아니면 아직 빠진 것 하나를 줄 번호와 함께 짚는다 (정답을 바로 말하지 않음)
- 기록은 `CODE#<id>` / `REVIEW#<첨삭 시각>#RETRY#…` 에 저장. 처음 첨삭의 ○△✕ 개수는 바꾸지 않는다

## 6. AI 튜터 대화
- 첨삭을 받은 뒤, 메모별 첨삭 하나(가장 최근 첨삭의 항목)에 대해 묻는다. 메모 하나에 **10번**, 질문은 300자까지
- 시스템 프롬프트에 코드 전체(줄 번호)·그 범위·학습자 메모·판정·코멘트·모범 설명을 넣고, 지난 대화를 이어서 보낸다
- **튜터 규칙**: 이 코드와 범위를 이해하는 데만 답하고 새 코드를 대신 짜 주지 않는다. 처음에는 볼 줄과 생각할 질문으로 이끌고, 학습자가 이미 시도했거나 직접 설명을 원하면 예시 값을 넣어 줄 단위로 풀어 준다. 2~5문장
- 답과 함께 `lookAt`(다시 볼 줄 0~3개)을 받아, 화면에서 누르면 왼쪽 전체 코드에 표시한다
- 대화는 `CODE#<id>` / `REVIEW#<첨삭 시각>#CHAT#…` 에 저장되어 다시 열어도 남고, 읽을 코드와 함께 지워진다
