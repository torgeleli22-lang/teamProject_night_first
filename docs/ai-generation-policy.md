# AI 사용 기준 (코드 리딩 노트)

> AI 는 네 가지 작업에만 씁니다. 모두 `lambda/api/common.py` 의 `ask_ai()` 로 부르고, 응답은 정해진 JSON 모양(도구 입력)으로 받아 검사합니다.
> AI 를 쓸 수 없을 때(관리자가 끔 · `AI_MODE=off` · 월 예산 · 요청 한도 · 형식 오류)는 **AI 없이 같은 화면이 계속 동작**합니다.
> 관리자 화면 `/admin/` 에서 작업별 호출 수·토큰·이번 달 추정 비용을 봅니다.

| 작업 (`USAGE` 이름) | 파일 | 언제 | AI 없을 때 |
| --- | --- | --- | --- |
| 주제 판정 `topic_check` | `topics.py` | '직접 적기' 주제를 낼 때 | `rule_check`: 금지어 → 부적절, 막연한 말 → 제안 3개, 큰 단어(입문·초급은 엄격) → 좁힌 주제 |
| 연습 코드 만들기 `code_generation` | `practice.py` | 코드 받기, 더 쉽게·더 어렵게 | `samples.py` 의 예시 코드 (같은 난이도, 같은 주제 → 최근에 안 푼 주제) |
| 내 코드 분석 `code_inspection` | `inspect_code.py` | '메모하러 가기' | `rule_analysis`: 문법 요소로 난이도, 함수마다 조건·반복 덩어리를 ※ 로 |
| 빨간펜 첨삭 `review` | `review.py` | '첨삭 받기' | `rule_review`: 겹치는 ※ 지점의 핵심 표현이 메모에 얼마나 있는지로 ○△✕ |

## 1. 주제 판정
- **ok**: 그 난이도의 길이(입문 10~20줄, 초급 25~45줄, 중급 35~60줄) 안에서 기능 하나를 보여 줄 수 있는 구체적인 생활 속 주제 → 바로 코드 만들기
- **vague**: 무엇을 하는 코드인지 알 수 없음 ("재미있는 거") → 구체적인 주제 3개
- **too_big**: 기능이 여러 개 ("쇼핑몰 만들기") → 첫 제안은 기능 하나로 좁힌 주제. 난이도가 낮을수록 엄격하게
- **inappropriate**: 해킹·불법·폭력·혐오·성적인 내용이거나 코드와 관계없음 → 만들지 않음, 화면은 "랜덤으로 뽑을게요"
- 주제는 50자까지. 학습자가 적은 글은 `<topic>` 안의 데이터로만 다룬다

## 2. 연습 코드 만들기
- AI 가 `title`, `code`, `marks`(※ 2~4곳: 입문 2곳, 그 밖 3곳)를 만든다. ※ 마다 `startLine`·`endLine`(그 줄의 글자 그대로), `startNo`·`endNo`(줄 번호 힌트), `why`, `explanation`(모범 설명), `keywords`
- 서버 검사 (`check_generated`): ① `compile()` 로 문법 확인 (실행하지 않음) ② 난이도별 최대 줄 수(30·60·80) ③ ※ 줄을 코드에서 찾기 (글자 우선, 같은 줄이 여럿이면 번호 힌트에 가까운 줄) ④ 겹치지 않는 ※ 2곳 이상
- 실패하면 이유를 알려 주고 **한 번 더**, 그래도 실패하면 예시 코드 (화면에 안내 문구)
- **더 쉽게·더 어렵게**: 지금 코드와 어려웠던 이유(너무 긺·모르는 개념·흐름이 복잡)를 주고 주제는 그대로 다시 만든다. 처음 코드부터 **5번까지** (`rootId`·`regenCount`), 난이도는 한 단계씩(입문~중급 안에서)

## 3. 내 코드 분석
- 화면에서 먼저: `.py` 확인, 300줄 확인, 민감 정보 가리기(`src/lib/secrets.ts`) → 가린 코드만 보낸다
- `POST /inspect` (AI 없음): 한 번 더 가리기, 함수·메서드 목록(들여쓰기로 끝 줄), 훑어본 난이도(규칙)
- `POST /inspect/start` (AI): 고른 함수 범위 안에서 난이도(1~3)·이유·※ 2~4곳. 범위 밖 ※ 는 버리고, 하나도 없으면 규칙 분석
- 올린 코드는 1일 뒤 DynamoDB TTL 로 지워진다. 코드는 `<user_code>` 안의 데이터로만 다룬다

## 4. 빨간펜 첨삭
- **누락(⬚)은 AI 없이** 정한다: ※ 범위와 겹치는 메모가 하나도 없으면 누락
- AI 는 메모마다 correct / partial / wrong, `comment`(1~2문장), `lookAt`(다시 볼 줄 1~3개), `model`(모범 설명)과 총평 `summary`, 누락 ※ 마다 힌트 한 문장을 낸다
- **코멘트 규칙 (가장 중요)**: 정답을 바로 알려 주지 않고, 다시 볼 곳(줄 번호·조건·값)을 짚어 스스로 고치게 한다. 정확하면 잘 짚은 점을 칭찬하고 하나 더 볼 점
- ※ 지점과 겹치는 메모의 모범 설명은 AI 가 아니라 코드를 만들 때 정해 둔 `explanation` 을 쓴다 (첨삭마다 기준이 흔들리지 않게)
- 메모는 20장·500자까지. 메모 글은 `<memo>` 안의 데이터로만 다룬다
- 모범 설명은 첨삭 결과에서 '모범 설명 보기'를 눌러야 보인다

## 비용 안전장치
- 월 예산 **$10** (`AI_MONTHLY_BUDGET_USD`): 이번 달 쓴 금액 + 이번 호출의 최대 비용이 예산을 넘으면 부르지 않는다
- 요청 한도: 학습자 1명 1시간 30번, IP 1개 1시간 300번, 서비스 전체 1시간 400번 (`common.LIMITS`)
- 같은 코드 다시 만들기 5번
- 관리자 **AI 끄기** (30초 안에 모든 실행 환경에 반영)

## 팀이 정해야 할 것
1. 첨삭 엄격함 — 부분 정답(△)을 얼마나 너그럽게 볼지 (`review.py` 의 `SYSTEM_PROMPT`)
2. ※ 지점 수 — 지금 입문 2곳, 초급·중급 3곳
3. 예시 코드 수 — AI 를 끈 동안 같은 코드를 다시 볼 확률
4. 월 예산·요청 한도
