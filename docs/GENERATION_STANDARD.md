# 연습 문항 생성 기준

AI 가 만드는 연습 문항(코드 + ※ 꼭 설명할 곳 + 모범 설명)이 **무엇을 갖춰야 학습자에게 내보낼 수 있는지** 정하는 문서예요.
코드(`lambda/api/practice.py`)의 프롬프트·규칙 검사·AI 검토는 이 문서를 따르고, 기준을 바꿀 때는 이 문서부터 고쳐요.

- 상태: **v1.3.1** (2026-11-03) — 변경은 맨 아래 `## 변경 기록` 에 남겨요
- 원칙
  - 위 단계가 아래 단계를 정해요: **학습 목표 → 코드 요건 → ※ 지점 → 모범 설명 → 합격 기준 → 실패 처리**
  - 모든 기준에는 **확인 방법**(규칙 검사 · AI 검토 · 실제 실행)이 붙어요. 확인할 수 없는 기준은 넣지 않아요
  - 숫자(줄 수 등)는 학습 목표를 담기 위한 결과예요
  - 서버에서는 생성된 코드를 실행하지 않아요. 대신 AI 가 실행 과정을 한 줄씩 따라간 **실행 추적표**를 모범 설명의 근거로 써요 (실제 실행이 아니라 시뮬레이션이에요 — 격리된 실행 환경은 학교 계정 권한 문제로 나중에)

## 0. 생성 흐름

```
① 출제 (code_generation)      코드 + ※ 위치·개념 (모범 설명은 아직 없음)
   → 규칙 검사 A               문법·금지 기능·난이도별 필수/금지 요소·손으로 따라갈 크기·줄 수·※ 개수/범위/중심 개념
   → (코드가 걸리면) 부분 수정 (code_fix)   줄 번호를 붙인 코드와 걸린 이유를 주고 바꿀 줄만 받아 고쳐요 (문항당 1번. 줄 수는 한도와 20% 안쪽 차이일 때만)
   → (※ 지점만 걸리면) ※ 다시 고르기 (mark_reselect)   코드는 그대로 두고, 줄 번호를 붙인 코드에서 ※ 만 다시 골라요 (1번)
② 실행 추적표 (code_trace)     완성된 코드를 새로 읽고 실행 순서·분기·반복 횟수·변수 값을 추적 → 그 사실만으로 모범 설명
   → 규칙 검사 B               모범 설명: 빈 설명·길이·가정 표현(꼭 지킬 것) / 근거 없는 숫자(확인할 것)
                               핵심 표현은 서버가 고쳐요: 설명 안에 그대로 있는 말만 남기고, 모자라면 설명 속의 코드 이름·값으로 채워요
③ 교차 검토 (code_check)       생성 쪽 추적표를 보지 않고 원본 코드에서 따로 추적 → 실행 오류·난이도·모범 설명 판정, 틀린 설명은 고침
   → 규칙 검사 B 한 번 더       검토가 고친 설명까지 확인. 꼭 지킬 것이 남으면 ②·③ 만 한 번 더 (코드는 그대로), 그래도 남으면 다시 만들기
   → (검토가 코드 문제를 찾으면) 부분 수정이 아직이면 그 문제로 부분 수정 → 규칙 검사 A → ②·③ 다시
   → 두 추적표 비교 (서버)      ※ 지점마다 나갈 때 값·반복 횟수, 출력이 같은지 기록 (checks.traceAgree)
④ 제공                        verification: ai_reviewed (검토까지) / rule_checked (검토 AI 를 못 씀) / sample_verified (예시 코드)
```
- **고칠 수 있는 문제는 그 단계만 다시** 해요: 코드 문제는 먼저 **부분 수정**(바꿀 줄만), ※ 위치만 문제면 ※ 다시 고르기, 모범 설명만 문제면 ②·③ 다시. 부분 수정으로도 안 되거나 줄 수가 한도에서 20% 넘게 벗어났을 때만 이유와 고칠 방향을 붙여 ① 부터 **다시 만들어요 (최대 2번)**. 그래도 안 되면 같은 언어·난이도의 예시 코드
- 문항당 AI 호출은 보통 3번(출제·추적·검토). 부분 수정은 코드 전체가 아니라 바꿀 줄만 받으므로 다시 만들기보다 출력 토큰이 적어요
- **학습자 등급** (0.1) 은 ※ 고르기와 모범 설명의 말투·깊이만 바꿔요

### 0.1 학습자 등급 (`GRADES`)
난이도(코드가 얼마나 복잡한지)와 별개로, **같은 코드를 누구에게 어떻게 설명할지**를 정해요. 교차 검토(③)에는 주지 않아요 — 정확성은 등급과 상관없이 같은 기준이에요.

| 등급 | ※ 고르기 (①·※ 다시 고르기) | 모범 설명 (②) |
|---|---|---|
| 기초 `basic` | 프로그램의 큰 흐름(값이 들어와 바뀌고 나가는 곳) | 용어는 쉬운 말로 풀고, 값이 바뀌는 순서를 차례대로 |
| 보통 `standard` (기본) | 지금 기준 그대로 (프롬프트에 등급 줄을 넣지 않음) | 지금 기준 그대로 |
| 전문가 `expert` | 잘못 읽기 쉬운 곳(경계 조건·반복이 끝나는 순간·상태가 바뀌는 순간) | 정확한 용어, 왜 그 횟수·그 분기가 되는지까지 |

- 요청 본문 `grade` (`POST /practice`, 실험 `POST /admin/experiment`). 화면에서 고르는 곳은 아직 없어요 (기본 보통)

## 1. 난이도별 학습 목표

난이도는 **학습자가 머릿속에 동시에 붙잡고 따라가야 하는 것의 양**으로 나눠요. 네 가지 요소로 판단해요:
실행 흐름(순차·분기·반복·호출) · 상태 변화(변수·자료구조) · 데이터 전달(인자·반환값) · 실행 경로(예외·재귀·알고리즘 전략).

| 난이도 | 학습 목표 (학습자가 설명할 수 있어야 하는 것) | 중심 개념 (`CORE_CONCEPTS`) |
|---|---|---|
| **입문** | 위에서 아래로 실행되는 코드에서 **반복과 조건을 지나며 변수 값이 바뀌는 과정** | 반복이 값을 바꿈 · 조건 분기 |
| **초급** | **함수를 부르면 값이 넘어갔다 돌아오는 흐름**, 리스트·딕셔너리(배열·객체)가 바뀌는 과정 | 함수 호출 · 자료구조 다루기 |
| **중급** | **객체 상태 변화, 예외로 건너뛰는 흐름, 재귀**처럼 위에서 아래로 읽으면 놓치는 흐름 | 객체 상태 · 예외 흐름 · 재귀 |
| **고급** | 자료구조와 **알고리즘이 문제를 푸는 전략** — 무엇을 기준으로 고르고, 언제 값을 갱신하고, 언제 멈추는지 | 알고리즘 핵심 |

- 위 단계는 아래 단계 개념을 포함해요
- **집중 연습** ('내 공부'의 약한 개념): 그 개념이 그 난이도에서 쓰지 않는 요소면(예: 입문의 예외 흐름) 그 개념이 나오는 가장 낮은 난이도로 올리고 안내해요 (`FOCUS_MIN_LEVEL`). 이때 중심 개념은 집중 개념이에요

### 2.1 난이도별
| 항목 | 입문 | 초급 | 중급 | 고급 |
|---|---|---|---|---|

| 쓰지 않는 것 (위 단계 개념) | 함수 정의 2개 이상, 클래스, 예외 처리, 재귀 | 클래스, 재귀 | — | — |

- 길이는 실행 추적표의 정확도에 맞췄어요 (긴 코드일수록 추적이 틀리기 쉬워요)
- "손으로 따라갈 크기"는 추적표를 짧게 유지하는 데도 필요해요

### 2.2 공통
| 항목 | 기준 | 확인 |
|---|---|---|
| 문법 | 문법 오류 없음 (오류가 있으면 몇 번째 줄의 무엇인지 알려 주고 다시 만들어요) | 규칙 — Python `ast`, JavaScript tree-sitter(문법 나무) |
| 실행 | 오류 없이 끝나고 결과를 출력 | 규칙(출력 존재) · AI 검토(실행 오류) |
| **같은 결과** | 실행할 때마다 출력이 같아요. Python `random`·`time`·`secrets`·`uuid`·`now()`·`today()`, JavaScript `Math.random`·`Date.now()`·인자 없는 `new Date()` 금지. 날짜는 `datetime(2026, 3, 2)` 처럼 정해진 값 | 규칙 |
| 외부 의존 없음 | 입력·파일·네트워크·운영체제·다른 프로그램 실행 없음, 표준 라이브러리만 | 규칙 |
| 결과가 보이는 출력 | ※ 지점의 결과가 드러나도록 중간 결과와 마지막 결과를 출력 | 프롬프트 지시 |
| 쓸모없는 코드 없음 | 실행되지 않는 함수, 결과에 안 쓰이는 계산, 줄 수 채우기 없음 | AI 검토 |
| 주제·이름·주석 | 고른 생활 주제를 다룸, 이름은 영어, 문자열·주석은 한국어, 주석은 제목 정도 | 프롬프트 지시 |

## 4. 모범 설명과 실행 추적표

### 4.1 실행 추적표 (② code_trace) — 모범 설명보다 먼저
| 칸 | 내용 |
|---|---|
| `flow` | 프로그램 시작부터 끝까지 실행 순서 요약 (최대 40단계): 줄·사건(call·return·assign·branch·loop·raise·catch·print)·무엇이·그 직후 변수 값 |
| `output` | 실제로 출력되는 줄 |
| ※ 지점마다 `enter` · `steps` · `exit` | 들어갈 때 값(앞의 실행으로 이미 바뀐 값 포함) → 구간 안의 변화 → 나갈 때 값 |
| `branch` · `count` | 실제로 실행된 분기, 반복·재귀 횟수 |

- 출제와 분리된 호출에서 **완성된 코드를 새로 읽고** 추적해요 (출제자의 의도가 아니라 코드가 실제로 하는 일을 따라가게)
- 저장만 하고 화면에는 보내지 않아요 (CODE#<id> INFO 의 `trace`)

### 4.2 모범 설명
| 항목 | 기준 | 확인 |
|---|---|---|
| 근거 | **추적표에 있는 사실만** | 규칙 B (숫자) · AI 검토 |
| 순서 | 들어오는 값 → 거치는 흐름 → 결과 (실제 값 1개 이상) | 프롬프트 지시 · AI 검토 |
| 길이 (`EXPLANATION_MAX`) | 2~3문장, 300자 이하 | 규칙 B (꼭 지킬 것) |
| 가정 표현 | "예를 들어"·"예컨대"·"가령" 금지 | 규칙 B (꼭 지킬 것) |
| 핵심 표현 | 3~5개, 모범 설명 안에 그대로 있는 말. 설명에 없는 것은 서버가 빼고, 2개 미만이면 문제 | 규칙 B (꼭 지킬 것) |
| 근거 없는 숫자 | 설명 속 숫자가 추적표·출력·코드 어디에도 없으면 교차 검토에 알려 확인 (줄 번호는 제외) | 규칙 B (확인할 것) |
| 여러 번 실행되는 구간 | 결과가 가장 잘 드러나는 한 번을 골라 그 기준으로, 몇 번째 호출인지 밝힘 | 프롬프트 지시 |
| 말투 | 한국어 존댓말 "~해요", 초보자 눈높이 | 프롬프트 지시 |

### 4.3 첨삭 판정 (참고 — `review.py`)
○ 정확: 흐름과 결과를 정확히 · △ 부분: 맞지만 중요한 조건·순서·결과가 빠짐 · ✕ 오해: 실제와 다르게 이해 · ⬚ 빈칸: ※ 지점에 메모 없음 (규칙)

## 5. 합격 기준

| 단계 | 다시 만들게 되는 것 | 고치고 넘어가는 것 | 기록만 하는 것 |
|---|---|---|---|
| 규칙 검사 A | 크기(줄 수) 문제, 부분 수정 뒤에도 남은 코드 요건 | 2장 코드 요건(문법·금지 기능·필수/금지 요소) → 부분 수정 1번. 3장 ※ 위치(범위·겹침·개수·줄 찾기·중심 개념)만 걸리면 ※ 다시 고르기 1번 — 그래도 걸리면 다시 만들기 | — |
| 규칙 검사 B (검토 뒤) | 빈 설명, 300자 초과, 가정 표현 — ②·③ 을 한 번 더 해도 남을 때 | 핵심 표현: 설명에 없는 말 빼기, 2개 미만이면 설명 속 코드 이름·값으로 채우기 (그래도 2개 미만일 때만 꼭 지킬 것) | 근거 없는 숫자 (`checks.unsupported`) |
| 교차 검토 | 부분 수정 뒤에도 남은 실행 오류·끝나지 않는 반복·난이도 불일치·실행되지 않는 ※·쓸모없는 코드 | 위 코드 문제 → 부분 수정 1번(아직 안 썼으면) 후 ②·③ 다시. 틀린 모범 설명 → 검토의 추적 기준으로 고친 설명 | — |
| 두 추적표 비교 | — | — | ※ 지점별 일치·출력 일치 (`checks.traceAgree`·`outputAgree`) |

- 예시 코드(`samples.py`·`samples_js.py`)는 위 기준을 모두 지키고, `npm run verify` 가 **실제로 실행**해 확인해요 (`sample_verified`)

## 6. 실패 처리

| 상황 | 처리 |
|---|---|
| 규칙 검사 A 에 ※ 위치만 걸림 | 코드는 그대로, 줄 번호를 붙인 코드와 걸린 이유를 주고 ※ 만 다시 고르기 (`mark_reselect`, 1번) → 다시 규칙 검사 A |
| 규칙 검사 A 에 코드 요건이 걸림 (줄 수는 한도와 20% 안쪽 차이일 때만 — 길면 덜 중요한 줄 빼기, 짧으면 이어지는 작은 기능 더하기) | 줄 번호를 붙인 코드와 걸린 이유를 주고 바꿀 줄만 받기 (`code_fix`, 문항당 1번) → 다시 규칙 검사 A. ※ 줄이 바뀌어 ※ 만 남으면 ※ 다시 고르기 |
| 줄 수가 한도에서 20% 넘게 벗어남, 부분 수정·※ 다시 고르기도 실패 | ②·③ 은 건너뛰고, 이유 + 고칠 방향(줄일 양·지킬 개수·범위)을 붙여 ① 부터 다시 |
| 검토 뒤에도 남은 모범 설명 문제 | 코드는 그대로 ②·③ 한 번 더, 그래도 남으면 ① 부터 다시 |
| 교차 검토가 찾은 코드 문제 (실행 오류·난이도 등) | 부분 수정을 아직 안 썼으면 그 문제로 부분 수정 → 규칙 검사 A → ②·③ 다시. 이미 썼거나 고쳐지지 않으면 문제 목록을 붙여 ① 부터 다시 |
| 다시 만들기 2번 뒤에도 걸림 | 같은 언어·난이도(집중 개념 우선)의 예시 코드 + 안내 문구 |
| AI 를 쓸 수 없음 (꺼짐·월 예산·요청 한도·응답 형식 오류) | 출제·추적 단계면 바로 예시 코드. 검토 단계면 규칙 검사만 믿고 통과 (`rule_checked`) |
| 기록 | 걸린 이유는 관리자 'AI 호출 기록'에 남기고, 실험 경로(`POST /admin/experiment`)는 시도마다 단계별 결과를 돌려줘요 |
