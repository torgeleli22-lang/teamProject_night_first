# 연습 코드 생성·검증 기준 (v2)

AI 가 만든 코드가 **무엇을 갖춰야 학습자에게 내보낼 수 있는지**, 그리고 **채점 기준을 무엇으로 정하는지**를 정하는 문서예요.
코드(`lambda/jojo_practice/`)의 프롬프트·규칙 검사는 이 문서를 따르고, 기준을 바꿀 때는 이 문서부터 고쳐요.

- 상태: **v2.1** (2026-11-05) — 변경은 맨 아래 `변경 기록`
- 목적: 정답 값을 맞히는 곳이 아니라 **학습자가 코드의 흐름을 이해하고 설명할 수 있게** 연습시키는 곳이에요
- 원칙
  - 난이도는 **코드 길이나 문법 개수가 아니라 6가지 요소**로 정해요 (1장)
  - 생성과 검증을 나눠요: **생성 AI 1번 + 검토 AI 1번**. **생성은 Claude Haiku 4.5, 검토는 다른 회사의 모델 GPT-5.6 Luna** (둘 다 Bedrock). 같은 모델이면 같은 곳을 함께 잘못 볼 수 있어서 교차 검증은 다른 모델로 해요
  - 검토 AI 가 실제로 실행하듯 따라간 기록은 버리지 않고 **채점 기준으로 저장**해요
  - 모듈·랜덤·시각·입력 등 **언어 기능은 금지하지 않아요**. 값이 정해지지 않는 곳은 검토 AI 가 값을 정하고 "가정"으로 표시해요
  - 서버는 코드를 실행하지 않아요. 검토는 AI 가 실행을 따라가는 시뮬레이션이에요

## 0. 흐름

```
학습자: 언어(Python·JavaScript) · 난이도(초급·중급·고급) · 주제(랜덤 또는 직접 입력)
① 생성 AI   (code_generation, Claude Haiku 4.5)  난이도 기준(6요소)을 그대로 받아 코드를 만든다
   → 규칙 검사 1 (AI 없음)     문법 오류 · 빈 코드 · 너무 긴 코드(300줄)
② 검토 AI   (code_review, GPT-5.6 Luna)      코드를 실행하듯 따라간다 → 실행 기록 · 동작 판정 · 난이도 판정(6요소) · 흐름 단위별 모범 설명
   → 규칙 검사 2 (AI 없음)     실행 기록이 코드의 함수·반복문을 빠짐없이 다뤘는지 · 모범 설명이 있는지
③ 통과        화면에는 코드와 '설명할 곳(※)' 줄 범위만. 실행 기록·모범 설명은 저장해 두고 채점에만
   걸리면     코드 문제 → 부분 수정(바꿀 줄만) 1번 → ② 다시 / 난이도 불일치 → 검토 의견을 붙여 ① 다시 1번 / 그래도 안 되면 준비된 예시 코드
```
- 문항당 AI 호출: 보통 **2번**(생성·검토), 최대 **6번** (`MAX_CALLS`)

## 1. 난이도 6요소

| 요소 | 무엇을 보나 |
|---|---|
| ① 문법 복잡도 | 변수·자료형·연산자 같은 기본 문법부터 조건문·반복문·함수·클래스까지 어느 수준의 문법을 쓰는지 |
| ② 코드 구조 | 단순한 순차 구조인지, 여러 구문이 결합되거나 중첩된 구조인지 |
| ③ 논리적 복잡도 | 단순한 연산·조건 판단인지, 여러 조건을 조합하거나 복합적인 추론이 필요한지 |
| ④ 데이터 처리 | 단일 변수·기본 자료형인지, 리스트·배열·딕셔너리 같은 자료구조나 여러 데이터 사이의 관계를 다루는지 |
| ⑤ 실행 흐름 | 순차 실행인지, 분기·반복·함수 호출과 반환이 섞인 흐름인지 |
| ⑥ 개념 간 연계 | 하나의 개념 중심인지, 여러 개념(조건+반복, 함수+자료구조 …)을 결합하는지 |

## 2. 난이도별 생성 기준

| 난이도 | 대상 | 기준 |
|---|---|---|
| **초급** | 프로그래밍을 처음 배우는 사람 | 변수·자료형·기본 연산자 중심 · **하나의 핵심 개념** · 실행 순서와 결과가 쉽게 보이게 · 복잡한 조건·중첩 최소화 · 불필요한 함수·클래스·외부 라이브러리 지양 |
| **중급** | 기본 문법을 아는 사람 | 조건문·반복문·함수를 복합적으로 · **두 가지 이상의 개념 연계** · 여러 변수와 데이터를 처리 · 분기와 반복 흐름 · 매개변수·반환값으로 데이터 전달 |
| **고급** | 기본 개념을 충분히 아는 사람 | 중첩 반복·복합 조건식 · 함수·자료구조·클래스 등 **여러 개념 연계** · 함수 간 호출과 데이터 전달 · 여러 단계의 실행 흐름과 데이터 변경 · 복합적인 논리적 사고가 필요한 문제 |

## 3. 생성 AI 에게 주는 규칙 (프롬프트)
1. 지정한 난이도가 우선 기준이다. 같은 주제도 난이도에 따라 문법·구조·논리 복잡도를 다르게 한다
2. 그 난이도에 맞는 개념을 쓴다. 초급은 기본 문법 중심, 중급·고급은 개념을 점진적으로 결합한다
3. 주제와 관계없는 문법·기능을 덧붙이지 않는다. 특정 문법을 배우는 코드라면 그 문법이 핵심 역할을 하게 한다
4. **코드 길이는 난이도 기준이 아니다.** 짧아도 논리가 복잡하면 높은 난이도, 길어도 단순 반복이면 낮은 난이도다
5. 명확한 변수명과 일관된 구조. 난이도를 높이려고 일부러 읽기 어렵게 만들지 않는다
6. 실행 결과를 볼 수 있게 출력(print · console.log)을 넣는다
- 언어마다 문법은 달라도 판단 기준은 같다 (Python · JavaScript)

## 4. 검토 AI 가 하는 일 (② `code_review`)

코드를 **실제로 실행하듯 따라가며** 동작하는지 확인하고, 그 기록을 남겨요.

| 대상 | 하는 일 |
|---|---|
| 변수 | 코드에 정해진 값으로 따라가요 |
| 함수 | 매개변수에 값을 정해 넣고 실행하듯 따라가요 (호출하는 곳이 있으면 그 값으로) |
| 반복문 | 실제로 몇 번 도는지, 언제 멈추는지 확인해요 |
| 재귀 | 끝나는 조건(기저 조건)에 도달하는지, 반환값이 어떻게 쌓이는지 확인해요 |
| 값이 정해지지 않는 곳 | 랜덤·현재 시각·입력·외부 데이터는 값을 하나 정하고 `가정` 으로 표시해요 |

답 (`ReviewAnswer`)
- `units` — **흐름 단위**(함수 · 반복문 · 조건 분기 · 재귀 · 처리 덩어리)마다:
  줄 범위, 종류, `inputs`(넣은 값·가정), `steps`(값이 바뀌는 과정), `result`(나간 값·반환값), `count`(반복·재귀 횟수), `stop`(멈춘 조건),
  `explanation`(그 기록으로 쓴 **흐름 중심 모범 설명** 2~3문장), `keywords`(설명 속 핵심 표현), `key`(학습자가 꼭 설명해 볼 곳인지)
- `output` — 따라간 대로라면 출력되는 줄
- `runnable` · `problems` — 실제로 동작하는 코드인지, 아니면 "몇 번째 줄: 무엇이 왜"
- `level` — 6요소마다 판단한 난이도와 이유, 종합 난이도, 요청한 난이도와 맞는지(`match`), 맞추려면 무엇을 바꿀지(`advice`)

모범 설명 기준: **흐름 중심** — 무엇이 들어와 → 어떤 조건·반복을 거쳐 → 무엇이 남는지. 값은 흐름을 보여 주는 근거로 써요 (가정한 값이면 가정이라고 밝혀요). 2~3문장, 300자 이하, 한국어 존댓말 "~해요".

## 5. 규칙 검사 (AI 없음, 비용 0)

| 단계 | 규칙 | 걸리면 |
|---|---|---|
| 1 (생성 뒤) | 문법 오류 없음 (Python `ast` · JavaScript tree-sitter) | 부분 수정 |
| 1 | 코드가 비어 있지 않고 300줄 이하 | 다시 만들기 |
| 2 (검토 뒤) | 코드의 함수·반복문이 모두 어느 흐름 단위 안에 들어 있음 | 빠진 곳을 알려 주고 검토 1번 더 |
| 2 | 반복·재귀 단위에 `count`·`stop` 이 있음, 모든 단위에 모범 설명이 있음(300자 이하) | 검토 1번 더 |
| 2 | 설명할 곳(`key`) 1곳 이상 (없으면 함수·반복 단위를 서버가 고름, 최대 5곳 · 겹치면 바깥 것 하나만) | 고치고 넘어감 |
| 판정 | `runnable=false` 또는 `problems` 있음 | 부분 수정 → ② 다시 |
| 판정 | `level.match=false` | `advice` 를 붙여 ① 다시 |

## 6. 실패 처리

| 상황 | 처리 |
|---|---|
| 문법 오류 · 동작하지 않음 | 줄 번호를 붙인 코드와 문제를 주고 **바꿀 줄만** 받기 (`code_fix`, 문항당 1번) → 다시 검사 |
| 난이도 불일치 | 검토의 `advice` 와 지금 코드를 주고 ① 다시 (1번) |
| 그래도 걸림 · AI 호출 한도(6번) · AI 를 쓸 수 없음 | 같은 언어·난이도의 **예시 코드** (`samples.py`, `npm run verify` 가 실제 실행으로 확인) |
| 검토 AI 답의 형식 오류 | 빠진 칸을 알려 주고 1번 더 묻기(`ai.py`). 그래도 틀리면 다시 만들기 — **검토를 거치지 않은 코드는 내보내지 않아요** |

## 7. 채점 기준 (`jojo_review`)

학습자는 코드에 형광펜으로 줄 범위를 고르고 흐름을 설명하는 메모를 써요. 채점은 **검토 AI 의 실행 기록**을 기준으로 해요.

- 메모와 겹치는 흐름 단위의 `inputs`·`steps`·`result`·`count`·`stop`·`explanation` 을 채점 AI 에게 기준으로 줘요
- 판정은 **흐름을 이해했는지**로: ○ 순서·조건·결과의 의미가 맞음 (숫자가 조금 달라도) · △ 큰 흐름은 맞지만 중요한 조건·순서가 빠짐 · ✕ 흐름을 다르게 이해함
- ⬚ 빈칸: 설명할 곳(`key`) 중 메모가 하나도 겹치지 않은 곳 (규칙)
- 첨삭 문장은 정답을 바로 주지 않고 다시 볼 줄·조건을 짚어요. 결과 화면에 모범 설명과 실행 기록을 보여 줘요
- 채점 AI 를 쓸 수 없으면 핵심 표현이 메모에 들어 있는 비율로 규칙 채점
