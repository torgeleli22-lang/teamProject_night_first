## 1. 연구 질문과 가설

**연구 질문**: 출제·교차 검토 단계에서 판정 전에 변수 값을 줄 단위로 추적하게 하면(값 추적), AI 가 만든 ※ 모범 설명이 실제 실행 결과와 더 잘 맞는가?

| 가설 | 내용 | 종류 |
|---|---|---|
| **H1 (주가설)** | 값 추적을 켠 조건의 **※ 지점 실행 일치율**이 끈 조건보다 높다 | 우월성 |
| H2 | 값 추적을 켜도 **AI 문항 최종 제공률**이 5%p 넘게 떨어지지 않는다 | 비열등성 (한계 5%p) |
| H3 | 값 추적의 비용(문항당 시간·토큰)이 얼마나 늘어나는지 보고한다 | 기술 (검정 없음) |

논문의 "고정된 모범 설명 덕분에 첨삭 기준이 흔들리지 않는다"는 주장은 이 실험으로 입증하지 않아요. 측정하려면 `## 8. 추가 실험 (선택)` 을 따로 해요.

## 2. 비교 조건

값 추적 **하나만** 다르고 나머지는 모두 같아야 해요.

| 조건 | 출제 값 추적 | 검토 값 추적 | 생각 단계(extended thinking) |
|---|---|---|---|
| **A. 기준** | 끔 | 끔 | 끔 |
| **B. 값 추적** | 켬 (`trace` 칸이 `explanation` 보다 앞) | 켬 (`trace` 칸이 `ok` 보다 앞) | 끔 |
| C. 생각 단계 (탐색, 선택) | 끔 | 끔 | 켬 |

- 생각 단계는 논문에 없는 변수라 A·B 에서는 **반드시 끄고**, 넣는다면 C 로 따로 보고해요 (주가설 검정에 쓰지 않음).
- 조건은 코드 수정·재배포가 아니라 **실험 요청의 옵션**으로 바꿔요. 같은 배포(같은 커밋)에서 A·B 를 함께 돌려요.

### 고정하는 것 (두 조건 공통)
| 항목 | 값 |
|---|---|
| 모델 | Bedrock `us.anthropic.claude-haiku-4-5-20251001-v1:0` (출제·검토 같은 모델) |
| 온도 등 추론 설정 | 기본값 그대로 (두 조건 같게, 기록에 남김) |
| 규칙 검사·재생성 횟수·예시 코드 | 서비스와 같음 (`practice.py`) |
| 주제 목록·순서 | `TOPIC_POOL` / `ADVANCED_TOPIC_POOL` 에서 `--seed 2026` 으로 뽑은 목록 |
| 코드 버전 | 같은 git 커밋 (기록에 SHA) |

### 짝 맞추기와 순서
- 문항 하나 = (언어, 난이도, 주제, 반복 번호). **같은 문항을 A·B 에서 한 번씩** 만들어 짝을 지어요.
- 시간에 따른 차이(모델 부하 등)가 한쪽에 몰리지 않게 **A·B 를 번갈아** 요청해요 (A1, B1, A2, B2 …).

## 3. 표본 크기

### 계산 근거
※ 지점 일치율 두 비율의 차이를 유의수준 0.05(양측), 검정력 0.8 로 찾으려면 조건마다 필요한 ※ 지점 수:

| 기준 조건 일치율 → 값 추적 조건 일치율 | 조건당 필요한 ※ 지점 |
|---|---|
| 77% → 90% (본 실험 2차의 10문항 표본 수준) | 약 125곳 |
| 85% → 93% | 약 237곳 |
| 90% → 96% | 약 280곳 |
| 92.7% → 96.8% (논문 초안의 값) | 약 461곳 |

- 문항당 ※ 지점은 평균 2.75곳(1·2·3·5곳)이고, AI 문항이 약 95% 라서 **40문항 ≈ 105곳**이에요. 40문항으로는 차이가 10%p 이상일 때만 유의하게 나올 수 있어요.
- 한 문항 안의 ※ 지점끼리는 서로 비슷한 경향이 있어서(같은 코드), 실제로는 위 수보다 1.2~1.5배가 필요해요.

### 결정 (초안)
- **조건당 120문항** (언어 2 × 난이도 4 × 15회) → 조건당 ※ 약 310곳, 두 조건 합계 240문항
- 90% → 96% 정도의 차이를 찾을 수 있는 크기예요. 기준 일치율이 그보다 낮으면 더 작은 차이도 찾아요.
- 예비 실험(조건당 8문항)은 파이프라인 점검용으로만 쓰고 결과에 넣지 않아요.

### 비용·시간 (예상)
- 문항당 약 0.03~0.08달러 → 240문항 약 **8~20달러**, 4개씩 동시에 약 1.5~3시간
- 서비스의 월 AI 예산(`MONTHLY_BUDGET_USD`, 10달러)을 넘을 수 있어요. 실험 기간에만 올리거나 며칠에 나눠 돌려야 해요.

## 4. 지표 정의

### 주지표
**※ 지점 실행 일치율** = 일치로 판정된 ※ 지점 수 / 최종 제공된 AI 문항의 ※ 지점 총수

- 대상: 최종 결과가 AI 문항(`origin: ai`)인 문항의 ※ 지점 전부 (표본 추출 없이 전수)
- 판정 기준: `## 5. 일치 판정 기준`

### 보조 지표
| 지표 | 정의 |
|---|---|
| 문항 실행 일치율 | ※ 지점이 **모두** 일치한 AI 문항 수 / AI 문항 수 |
| 규칙 검사 재생성 판정 | 첫 생성이 규칙 검사에 걸린 문항 / 전체 문항 |
| 교차 검토 재생성 판정 | 첫 생성이 규칙은 통과했지만 교차 검토가 실행 오류·난이도 불일치를 찾은 문항 / 전체 문항 |
| 교차 검토의 모범 설명 교정 | 최종 AI 문항의 ※ 지점 중 교차 검토가 모범 설명을 바꾼 곳 / 그 ※ 지점 총수 |
| AI 문항 최종 제공률 | `origin: ai` 문항 / 전체 문항 |
| 예시 코드 대체율 | `origin: sample` 문항 / 전체 문항. 원인을 **검사 실패**와 **AI 호출 오류**(형식 오류·시간 초과·권한)로 나눠 보고 |
| 문항당 생성 시간 | 요청부터 최종 결과까지. 평균·중앙값·90번째 백분위 |
| 문항당 토큰·비용 | 입력·출력 토큰 합계와 모델 가격으로 계산한 비용 |

## 5. 일치 판정 기준

### 정답 만들기 (실제 실행, 오프라인)
- 코드는 **서비스 서버에서 실행하지 않아요.** 평가 도구가 격리된 곳(CloudShell·GitHub Actions·연구자 컴퓨터)에서 실행해요.
- **Python**: `sys.settrace` 로 ※ 지점 줄 범위를 지날 때마다 지역·전역 변수 값, 호출 순서, 반복 횟수를 기록하고, 전체 출력을 저장해요.
- **JavaScript**: node 로 실행한 출력을 저장하고, 필요한 경우 ※ 지점 줄 뒤에 값을 출력하는 줄을 끼워 넣은 사본으로 한 번 더 실행해요.
- 제한: 문항당 5초, 출력 20,000자. 실행 오류·시간 초과면 그 문항의 ※ 지점은 모두 **불일치**로 하고 원인을 기록해요.

### 모범 설명의 진술 나누기
모범 설명을 확인할 수 있는 진술로 나눠요.

| 종류 | 예 |
|---|---|
| 값 | "total 은 4500 이 돼요", "3권에서 2권으로" |
| 순서·호출 | "먼저 find 로 찾고 withdraw 를 불러요" |
| 횟수 | "재귀가 4번 호출돼요" |
| 분기 | "28도라 if 쪽이 실행돼요", "파티 5 는 배정되지 않아요" |
| 결과·출력 | "'안전한 비밀번호입니다'가 나와요" |

### ※ 지점 판정
| 경우 | 판정 |
|---|---|
| 확인할 수 있는 진술이 **모두** 실제 실행과 같음 | **일치** |
| 하나라도 다름 (값·순서·횟수·분기·결과) | **불일치** |
| 앞의 호출로 이미 바뀐 값을 반영하지 않음 (예: 먼저 빌려 간 책) | 불일치 |
| "예를 들어 ~라면"처럼 **가정임을 밝힌** 예시 | 그 가정 아래에서 코드 논리대로 맞으면 일치 |
| 가정임을 밝히지 않고 실제와 다른 값을 씀 | 불일치 |
| random·Math.random·현재 시각 때문에 실행마다 달라지는 값 | 값이 아니라 흐름이 맞는지로 판정 |
| 모범 설명이나 핵심 표현이 비어 있음 | 불일치 |
| 틀린 진술은 없지만 확인할 수 있는 진술도 없음 (흐름만 일반적으로 설명) | 일치. 단 **"구체 진술 없음"으로 따로 세어** 보고 |
| 표현만 다름 ("늘려요" ↔ "더해요") | 일치 |

### 판정 절차
1. **조건 가리기**: A·B 의 ※ 지점을 섞고 조건 표시를 지운 판정 시트를 만들어요 (판정자는 어느 조건인지 몰라요).
2. **1차 판정 (자동)**: 출제·검토에 쓰지 않은 다른 모델이, 실제 실행 기록(추적 값·출력)과 모범 설명을 비교해 진술마다 일치·불일치를 적어요.
3. **사람 판정**: 연구자 2명이 무작위 30% 표본과 1차 판정에서 불일치·애매로 나온 것 전부를 따로 판정해요.
4. **합의**: 두 사람이 다르면 논의해 정하고, 처음 판정의 일치도(Cohen's κ)를 보고해요. 자동 판정과 사람 판정의 일치도도 보고해요.
5. 최종 판정은 사람 판정이 있으면 사람 판정, 없으면 자동 판정이에요.

## 6. 분석 방법

| 가설 | 분석 |
|---|---|
| H1 ※ 지점 일치율 | 두 비율의 차이와 **문항 단위 부트스트랩 95% 신뢰구간** (문항을 다시 뽑아 같은 문항의 ※ 지점이 함께 움직이게, 10,000번). 차이의 신뢰구간이 0 을 넘으면 지지 |
| H1 보조: 문항 일치율 | 짝지은 문항(같은 언어·난이도·주제·반복)끼리 **McNemar 검정** |
| H2 최종 제공률 | 차이(B − A)의 95% 신뢰구간 하한이 −5%p 보다 크면 비열등 |
| H3 시간·비용 | 평균·중앙값·90번째 백분위와 증가량. 검정하지 않음 |

- 언어별·난이도별 결과는 **기술 통계로만** 보고해요 (칸마다 표본이 작아 검정하지 않음).
- 여러 지표를 보지만 주가설은 H1 하나예요. 보조 지표의 유의성은 탐색적 결과로 적어요.

## 8. 추가 실험 (선택): 첨삭 기준의 일관성

논문의 "고정된 모범 설명을 기준으로 해서 첨삭마다 기준이 흔들리지 않는다"는 주장을 입증하려면:
- 같은 코드·같은 메모를 같은 조건에서 5번씩 첨삭하고, ○△✕ 판정이 같은 비율을 비교해요.
  - 조건 ①: 고정된 모범 설명을 기준으로 첨삭 (현재 방식)
  - 조건 ②: 기준 없이 첨삭 AI 가 그때그때 판단
- 이 실험을 하지 않으면 논문 문장을 "기준을 고정하여 일관성을 높이도록 설계하였다"처럼 설계 의도로 낮춰 써요.
